# 대응 입력 밀도 실험

현재 목표는 같은 문제에서 입력을 더 촘촘하게 만들었을 때 나타나는 응답 변화를 진단하는 것입니다. BabyVision 전체 388문항 또는 과거와 같은 52문항을 사용합니다. 문제 선택에 정답·reference CoT를 사용하지 않습니다. 모델 입력은 이미지, 질문, 보기와 고정 suffix뿐입니다. 데이터 로더가 정답을 분리하고 inference 경계에서도 정답 필드를 거부합니다.

## 고정 조건과 처리

모델 ID/revision, 프롬프트, 출력 상한, 샘플링 설정, 같은 배치 내 질문 순서, 시드를 고정합니다. 기준 smart_resize로 얻은 가로·세로를 각각 약 √2배 확대하고 32픽셀 배수로 반올림하므로, 실제 시각 토큰 비율은 이미지에 따라 약 2배 전후로 달라집니다. ViT 16×16 패치 크기와 2×2 병합 구조는 바꾸지 않습니다. 원본 이미지는 한 번 전처리하며 보간·정규화 루틴은 같습니다.

양쪽 조건은 실제 배치 ID의 합에 base seed 42를 더한 같은 시드를 사용합니다. 메모리 부족으로 배치를 나누면, 기존 상위 배치 결과를 버리고 모든 조건을 동일한 하위 배치·시드에서 다시 실행합니다. 분할 계획은 재시도 전에 저장되므로 재개 시에도 같은 계획을 사용합니다.

같은 시드는 완전한 결정성을 보장하지 않습니다. GPU 연산의 비결정성과 샘플링에 따른 생성 경로 차이가 남습니다. 여러 시드, 모델 크기, 세부 유형에 걸친 일관성은 별도 검증해야 합니다.

## 기록과 재개

원본 데이터 archive SHA256와 metadata SHA256를 검증합니다. 선택 이미지의 SHA256와 질문 문자열을 기록합니다. 코드 소스 hash, Git commit, config, 질문/정답 key hash를 실행 fingerprint에 반영합니다. 다른 config·코드·질문으로 동일 RUN_ID를 이어가면 중단합니다.

GPU 이름, compute capability, dtype, Torch/CUDA와 주요 라이브러리 버전이 다르면 중간 실행에 섞지 않습니다. Python, 플랫폼, NVIDIA driver도 기록합니다. 코드 커밋은 감사용으로 보존하며, 코드 hash가 같고 문서만 바뀐 커밋은 같은 실행을 이어갈 수 있습니다.

완료 배치의 모든 조건을 하나의 JSON에 원자적으로 저장합니다. 저장 전 프로세스가 죽으면 해당 배치는 재계산하지만, 이미 저장된 배치는 건너뜁니다. Drive는 실험 결과 저장소이며 모델 학습 optimizer checkpoint를 구현한 것은 아닙니다. 현재 패키지는 평가·추론용이고 학습 루프는 포함하지 않습니다.

## 채점과 보고

자동 집계는 마지막 boxed 답의 정규화 일치만 사용합니다. boxed가 없는 명확한 답이나 여러 표현의 의미 동등성을 모두 처리하지 않습니다. 미추출을 시각 인식 오답이라고 단정하지 마세요. 보고서는 boxed 누락, 출력 상한, 실제 답변 원문을 함께 제시합니다. 공식 외부 LLM judge는 실행하지 않습니다.

전체 정답 수, 유형별 결과, 양쪽 정답 유지·개선·악화·실패 유지를 함께 봅니다. 기존 로컬 수동 의미 검토 점수와 새 자동 점수를 직접 혼합하지 않습니다. 해설의 정확성과 최종 정답의 정확성도 구분해야 합니다.

원본이 이미 작은 경우 확대는 새로운 시각 정보를 만들지 않습니다. 원본 축소를 줄이는 경우와 이미 작은 원본을 확대하는 경우를 구분해 분석하세요. 단일 paired run의 작은 점수 차이는 일반적인 성능 개선이나 SOTA의 증거가 아닙니다.
